# 0026. Key figures and charts as fenced blocks, drawn natively

**Decided.** A reply can hold two kinds of fenced block whose content is JSON: ```` ```kpi ```` (a row of key figures) and ```` ```chart ```` (bar, line, area or ring). The app draws them as SwiftUI views, the charts with Swift Charts (`App/Views/ReplyBlocks.swift`); everything else in the reply stays Markdown. The client tells the engine which blocks it draws (`Engine.open(blocks:)`), and the instructions describe only those, with their schema, whether or not the conversation has a system prompt of its own. Models without tools (the on-device one, [decision 0013](0013-apple-model-text-only.md)) aren't told about them. A block whose JSON doesn't fit the schema, or that has more series than there are colours, is shown as the code it is. While a reply streams, a block whose fence hasn't closed shows a breathing placeholder of its shape instead of half a JSON; once closed, it takes the placeholder's place and its marks grow from the baseline.

**Why.** Figures and series read better drawn than listed, and a model already writes JSON well. Keeping them in the reply's text, like formulas ([decision 0019](0019-latex-with-mathjax.md)), adds no concept: nothing is stored apart, nothing is generated as a file, the database still holds only the text, and copying a reply copies its source. This is not an artifact ([decision 0005](0005-one-shell-no-file-tools.md)): there is no separate document to keep, preview or edit, only another way to draw a block. Swift Charts is an Apple framework, so the dependency rule holds. The engine only names the blocks, so it still knows nothing about SwiftUI, and a client that draws none gets instructions without them.

**Cost.** The schema lives in two places, the instructions and the decoder, and they must change together. Values are strings formatted by the model, so they can't be summed or compared; charts take numbers. Five series at most, from the palette's warm family: neighbours are told apart by colour-blind readers in both themes, but in dark mode ochre and chestnut are close when they aren't neighbours, which is why the ring names every slice beside it. Charts aren't selectable as text; their Table view is. A block inside a list item still streams as code, since the placeholder only replaces the reply's last block.
